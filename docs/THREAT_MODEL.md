# DeleteAudit 仓库级威胁模型

## Overview

DeleteAudit 是面向单机 Windows 的删除审计系统。本仓库计划包含一个未来作为 Windows Worker Service 运行的高权限只读采集器、一个低权限 WPF 查看器、SQLite 结构化索引、按日 JSONL 原始事件日志，以及完整性检查点。系统目标是记录未来发生的文件和目录删除，重点覆盖 D 盘、用户桌面、文档和开发项目；它只审计与告警，不阻断删除、不终止进程、不写内核驱动。

主要运行面是 `src/DeleteAudit.Collector`、`src/DeleteAudit.Infrastructure`、`src/DeleteAudit.Domain` 和 `src/DeleteAudit.Viewer`。`db/schema.sql` 定义持久化安全不变量，`config/appsettings.example.json` 定义监控和保护范围。测试、文档和设计夹具不是生产运行面，不能拥有系统权限或修改 Windows 配置。

关键资产包括：删除事实及其原始证据；事件顺序与时间；执行者、进程和路径归因；会话与风险判定；JSONL/SQLite/manifest 的完整性；签名密钥；采集覆盖与缺口状态；以及原始 XML、命令行、用户名和 SID 中的敏感数据。最重要的安全结果是“证据不足时诚实降级”，而不是以猜测补齐字段。

Phase 1A 已实现的控制位于离线边界内：XML 解析器禁止 DTD/外部实体并按 Data Name 取值；低置信启发式不回填身份；SQLite 仓储不创建或迁移 schema；哈希链签名仅定义接口，测试实现明确声明不具备硬件防篡改能力。真实事件日志、USN、服务和系统配置仍未接入。

## Threat Model, Trust Boundaries, and Assumptions

### 信任边界

1. **Windows 内核、事件日志服务与 DeleteAudit Collector 之间**：Sysmon、Security XML、USN 记录、事件时间、PID、路径和消息字段都作为不可信输入解析。Collector 可以信任操作系统提供读取机制的权限边界，但不能假设事件一定完整、有序或一致。
2. **高权限 Collector 与本地交互用户/Viewer 之间**：Viewer 属于低信任区，只能通过有限的只读查询契约读取数据。搜索词、筛选器、分页参数和导出目标都是攻击者可控输入，不能成为 SQL、路径或 XML 注入入口。
3. **Collector 与 `C:\ProgramData\DeleteAudit` 之间**：数据库、WAL、JSONL、manifest、存档和状态文件跨越持久化边界。崩溃、磁盘耗尽、并发读取、离线修改和整体回滚都在威胁范围内。
4. **本机与外部锚点之间**：在没有外部追加写检查点时，本地管理员能取得所有权、替换程序、回滚数据或清除来源日志。因此本地哈希链不能单独证明抵抗管理员篡改。
5. **配置/部署者与运行时之间**：监控根、保护根、事件通道、证书、ACL 和保留策略是管理员控制输入。恶意或错误配置可能制造盲区、扩大敏感数据范围或造成资源耗尽。
6. **删除事件与进程富化之间**：Sysmon 1 等进程创建证据可能缺失或迟到。PID 会复用，只有 Process GUID 或带启动时间/boot identity 的 PID 才能跨时间可靠关联。

### 行为者与能力

- 普通本地用户可能创建恶意路径/文件名、触发高频删除、提交恶意 Viewer 查询，并尝试读取或干扰日志。
- 被入侵的用户态进程可能批量删除、伪装进程名、快速退出、制造 PID 复用压力或诱发日志洪泛。
- 本地管理员或 SYSTEM 级对手可清空事件日志、停用数据源、修改配置/时间、替换二进制、读取密钥并回滚本地数据；没有外部信任根时无法完全抵抗。
- 合法操作员可能误配保护目录、权限、时间、存储额度或数据源，并造成与攻击相似的缺口。
- 开发者控制源码、依赖和构建流程；测试夹具与构建脚本不得自动获得生产凭据或系统修改能力。

### 输入分类

- **攻击者可控**：文件路径/名称、用户名显示值、进程命令行、部分 XML 文本字段、事件频率与顺序、WPF 查询条件、可能被替换的本地日志文件。
- **操作员可控**：监控根、保护根、存档策略、ACL、证书、服务身份、数据保留、外部锚点与部署开关。
- **开发者可控**：schema 迁移、解析器、相关性规则、依赖版本、签名/序列化格式、发布产物。

### 必须保持的不变量

- 只有 Sysmon 23/26 或经明确规则确认的等价事实源能直接建立 confirmed 删除；4663 和 USN 不能单独归因已完成删除。
- 任何数据源缺失、日志清空、Record ID 回退、USN Journal ID 改变、队列丢弃或持久化失败必须成为可见覆盖缺口。
- 原始证据与风险历史只追加；同一来源事件幂等入库；跨来源证据不能重复计数。
- 所有相关性以 UTC、稳定进程身份、规范化路径或文件引用号为依据；PID 单独不具备长期身份含义。
- Viewer 和普通用户不能修改日志、配置、签名状态或采集控制面。
- 路径规范化、显示、搜索与导出不能访问被删除目标、跟随重解析点、执行命令或拼接 SQL。
- 风险引擎只发出告警，不调用拦截、进程控制、文件删除、清理或卷修改操作。
- 哈希、签名和 manifest 的安全声明必须匹配真实边界；没有外部锚点时不得声称抵抗本地管理员。

### 运行假设与非目标

- 未来部署者负责另行安装/配置 Sysmon 和 Security 审计；本项目不隐式改变这些设置。
- 系统主要检测部署后发生的删除，不承诺追溯部署前历史。
- 内核级 rootkit、已控制 hypervisor 的攻击者和硬件取证不在应用级保证范围内。
- 精确恢复被删除内容不是目标。Sysmon 23 的存档只面向明确批准的高价值目录，不能演变为全盘备份。
- 对本地管理员的强对抗需要外部不可变锚点、受保护密钥和独立监控，这不是单机本地文件能够完成的属性。

## Attack Surface, Mitigations, and Attacker Stories

### 事件解析与证据投毒

恶意进程可以制造超长路径、Unicode 混淆、大量事件和边界时间戳，尝试使解析器崩溃、耗尽内存或错误归因。相关风险包括 XML 解析问题、整数/十六进制转换错误、路径混淆、事件重复和无界队列。

设计缓解：使用禁止外部实体/DTD 的 XML 读取方式；限制单事件尺寸和队列容量；解析失败时保存原始证据并记录健康事件；使用 Windows 语义的大小写不敏感规范化但保留原值；事件幂等键包含 channel epoch；对所有数值做有界解析；背压不得静默丢弃。

### 错误归因与 PID 复用

攻击者可快速创建/退出进程，利用 PID 复用或让 4663、Sysmon 与 USN 到达顺序错乱，从而把删除归给无辜进程/用户。若仅按时间和 PID 联接，这一故事现实且影响审计可信度。

设计缓解：Process GUID 优先；否则使用 boot identity、PID 和进程启动时间；路径/文件引用号和 SID 参与评分；冲突证据并存且降低置信度；低置信关联在 Viewer 中明确标识。命令行和父进程只来自进程创建证据，不由进程路径反推。

### 日志篡改、回滚与来源清空

普通用户可能尝试修改 ProgramData 日志；管理员级对手可以清空 Windows 日志、停止 Collector、回滚整套本地数据或替换密钥。磁盘故障与崩溃也可能产生类似症状。

设计缓解：服务 SID/SYSTEM 最小写 ACL；Viewer 走只读 IPC；原始表和 JSONL 只追加；逐条、跨日哈希链；CNG/TPM 不可导出签名检查点；数据库/JSONL 双写核对；检测日志 epoch、USN Journal ID 和 checkpoint 回退；将签名检查点外部锚定。外部锚定缺失时，管理员回滚仍是明确残余风险。

### 路径与查看器注入

文件名、命令行和 XML 可包含控制字符、双向文本、类似标记或 SQL 片段。若 Viewer 把内容当 XAML/HTML/命令或 SQL 拼接，普通用户可造成错误展示、查询注入或任意文件访问。

设计缓解：WPF 使用纯文本绑定和显式编码；数据库查询全部参数化；查询字段使用白名单；导出采用应用生成文件名并要求显式目标；不自动打开路径、命令行或链接；原始 XML 只以文本查看。

### 资源耗尽与批量删除

真正的批量删除恰好会产生最高事件量。攻击者可用大量低价值路径淹没管线，延迟保护目录告警或耗尽磁盘。

设计缓解：保护根事件具有独立优先级；输入采用有界分区队列和公平调度；聚合计数 O(1)/O(log n)；记录背压和丢失；磁盘低水位进入 degraded 状态并发告警，但不自动清理。存储容量、保留与外部转储需要运维批准。

### 配置和权限边界错误

错误的包含/排除规则可能造成 D 盘、桌面、文档或开发项目盲区；过宽的 Sysmon 23 存档会复制敏感文件并迅速占满磁盘；Viewer 写权限会破坏审计链。

设计缓解：配置 schema 校验、规范化后重叠检测、启动时打印有效覆盖、保护根不允许被普通排除规则覆盖、23 存档只接受显式 allowlist、权限自检和只读 Viewer 契约。配置变化本身写入审计记录并触发链式检查点。

### 敏感数据泄露

原始 XML 和命令行可能包含用户名、文档路径、访问令牌或业务秘密。查看器、导出和备份可能扩大泄露面。

设计缓解：最小 ACL、字段级默认遮蔽、命令行按授权显示、导出审计、静态加密方案和密钥管理在部署阶段评审、明确保留期。由于全文审计与最小收集存在冲突，不能在未决定治理政策前承诺长期保留。

### 供应链与更新

Collector 未来可能高权限运行，恶意 NuGet 包、构建脚本或未签名更新可直接跨越信任边界。当前空载骨架不应通过模板方便性引入不必要依赖。

设计缓解：最小依赖面、锁定并审计依赖、可重复构建、发布物签名、SBOM、发布前安全扫描、服务二进制 ACL 和受控升级回滚。项目不包含自更新器。

## Severity Calibration (Critical, High, Medium, Low)

### Critical

- 低权限用户可借 Collector 的高权限实现任意代码执行、任意内核/系统操作或写入受保护位置。
- 审计更新/插件/解析路径可被远程或低权限攻击者利用，持久控制高权限服务并同时伪造/清除证据。
- 声称存在外部完整性保证但验证逻辑允许对手伪造受信签名检查点，导致关键审计可无痕重写。

仅由本地管理员完成的本地日志删除通常不单独定为 Critical，因为管理员已在假设中拥有主机控制权；若系统承诺独立外部不可变证据，则绕过该边界可能提升到 Critical。

### High

- 普通用户可稳定修改、截断或替换其他用户/全机的审计记录而不触发完整性告警。
- 相关性错误可被现实地操纵，使大规模保护目录删除被归给无辜进程或完全不告警。
- Viewer 查询或导出允许任意文件读取、SQL 注入或跨越服务权限边界。
- 事件洪泛可确定性饿死保护目录通道，且系统仍错误报告 healthy/complete。

### Medium

- 特定时序下的 PID 复用导致少量事件低置信误归因，但原始证据仍完整可复核。
- 普通用户可读取不应公开的命令行、用户名/SID 或敏感路径，但不能修改系统或审计证据。
- 崩溃恢复会造成可检测的重复、短暂告警延迟或有限缺口，并正确标为 degraded。
- 配置验证遗漏使某个非保护监控根静默不生效，但启动覆盖报告仍可被操作员发现。

### Low

- Viewer 的非安全性显示错误、排序异常或仅影响本用户的筛选状态。
- 不影响证据、覆盖或告警的诊断信息不一致。
- 需要本地管理员权限、仅造成管理员已经能够造成的本地可用性影响，且不违背外部完整性承诺。
- 测试/文档工具中的问题在无生产凭据、无发布路径、无系统权限的真实使用方式下通常为 Low 或不适用。
